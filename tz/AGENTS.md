# Правила для ИИ-агента (Claude Code, Cursor, GigaCode)

Положите в корень репозитория разработки три файла: этот, `TZ_finance-assistant.md` и `statement-demo.csv`. Больше ничего из репозитория документов не нужно.

## Источник требований — один

`TZ_finance-assistant.md` — единственный источник. Версия — в шапке, изменения — в Приложении В. Если в коде или задаче что-то расходится с ТЗ — прав ТЗ; спросите человека, а не угадывайте.

Как искать нужное:
- требование — `ФТ-xx` (раздел 6), критерий приёмки — `ПК-xx` (10.3), экран — `Э-xx`, лист — `Л-xx` (5.2);
- формулы — раздел 4, контрольные числа — Приложение Б;
- что входит в текущий релиз — 10.1.

## Порядок работы

1. Берите ФТ текущего релиза по порядку номеров. Одно ФТ или связная группа — один коммит, в сообщении номера ФТ.
2. Для расчётов (раздел 4) сначала тест по Приложению Б с «сегодня» = 03.10.2026, потом код.
3. Готово — когда проходят ПК, которые ссылаются на это ФТ, и есть доказательство: вывод теста, снимок экрана на 375 px или строка журнала.

## Нельзя нарушать

- Деньги считает код в `money/`, модель чисел не считает; число в тексте модели, которого нет в расчёте, — шаблон.
- Партнёр не получает чужих `share`, `saved`, доходов, трат и выписки — ни в интерфейсе, ни в API.
- Любой текст перед GigaChat проходит общую функцию маскирования.
- Файлы выписки и снимки не пишутся на диск и удаляются в `finally`.
- В журнале `events` нет сумм и текстов.
- Модель — только GigaChat. Лицензии зависимостей — без GPL и AGPL.

## Что нельзя без человека

- Коммитить ключи, токены, строки подключения, `.env`.
- Коммитить реальные выписки, снимки, фразы пользователей.
- Менять ожидаемые числа Приложения Б под свой код.
- Добавлять экраны и функции, которых нет в ТЗ.
- Создавать в репозитории новые документы с требованиями — предложения писать человеку.
