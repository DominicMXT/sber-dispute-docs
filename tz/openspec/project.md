# Finance Assistant — контекст проекта

Версия 25.09.2026 · владелец — продакт · источник требований — `prd/2026-09-25_mvp-prd.html` (БТ)

## Назначение

Веб-приложение (PWA) для пары с раздельными деньгами, которая копит на крупную общую покупку.
Человек пишет одну фразу («котёл 40 тысяч к 15 ноября, я могу 25») и сразу видит: сходится ли
покупка к сроку, сколько ему откладывать в день и сколько можно тратить на себя сегодня.
Выписка банка показывает, в каких своих тратах найдутся недостающие деньги.

Конкурс Sber500 × Disrupt, этап 1: открытие 03.10.2026, 50 реальных пользователей к 12.10.2026.

## Границы

**Делает:** разбор фразы и ссылки на товар, расчёт плана, приглашение партнёра без раскрытия
своих денег, «сколько на себя сегодня», разбор выписки CSV и PDF Сбера с советами к цели,
журнал событий для метрик конкурса.

**Сознательно не делает:** не хранит и не переводит деньги (это банки: копилка, сбор); не подключается
к банкам по API; не показывает партнёру остатки, траты и доходы; не ведёт общий бюджет месяца;
не хранит файл выписки; не использует модели кроме GigaChat.

## Стек (из заявки на конкурс)

| Слой | Что |
|---|---|
| Клиент | React + TypeScript, сборка Vite, PWA (манифест, установка на главный экран) |
| Сервер | Python 3.12, FastAPI, Pydantic v2 |
| База | PostgreSQL |
| Модель | GigaChat API через SDK `gigachat` (MIT), структурный ответ через function calling |
| Выписка PDF Сбера | `Sberbank2Excel` (MIT) — готовый разбор PDF-выписок Сбербанка, форматы до 2026 года |
| Страница товара | `extruct` (BSD-3) — schema.org Product (JSON-LD, microdata) и Open Graph |
| Аналитика | выгрузка журнала в CSV + панель на Apache Superset (Apache-2.0) или Redash (BSD-2) |
| Хостинг | облако программы, серверы в РФ |

Лицензии: GPL и AGPL запрещены — права на код по Положению могут отчуждаться. Поэтому **не** Metabase и **не** Grafana.

## Доменные понятия

| Термин | Определение | В коде |
|---|---|---|
| Покупка | крупная общая трата с суммой и сроком | `Purchase` |
| Моя часть | сколько вносит этот человек; «плачу сам» = вся сумма | `share` |
| Недостача | сумма − части обоих, не меньше нуля | `gap` |
| Перебор | части обоих − сумма, не меньше нуля | `over` |
| Откладывать в день | (моя часть − отложено) ÷ дней до срока, вверх до рубля | `per_day` |
| Отложено | сумма отметок «отложил» минус «взял из отложенного» | `saved` |
| Приход в месяц | доход человека; вручную фразой или из выписки | `income_month` |
| Обязательные | регулярные платежи в месяц | `mandatory_month` |
| На себя сегодня | дневной лимит минус траты сегодня | `left_today` |
| Совет | шаг экономии с суммой в месяц и вкладом к сроку | `Tip` |
| Автоподбор | минимальный набор советов, закрывающий недостачу при первом показе | `auto_pick` |
| Реальный пользователь | физлицо с событием `purchase_answer_shown`, не команда и не знакомые | метрика |

## Инварианты — не ломаются никогда

1. **Деньги считает код.** Все суммы, доли, дни, остатки и советы — детерминированные функции с тестами. Модель чисел не считает.
2. **Числа в тексте модели сверяются с расчётом.** Если число в ответе GigaChat не совпало — показывается шаблонный текст.
3. **Партнёр видит только общую покупку:** название, сумму, срок, собрано вместе, свою часть и «по плану / отстаёт» у второго. Ни остатков, ни трат, ни доходов, ни выписки.
4. **В GigaChat уходит только маскированный текст.** Номера карт и телефоны заменяются до отправки; имена в описаниях операций — тоже.
5. **Файл выписки не хранится.** Разобрал — удалил, в базе только сводка.
6. **В журнале нет сумм и текстов.** Только события, компонент, результат, коды ошибок, хэши.
7. **Только GigaChat.** Другие поставщики моделей не подключаются.

## Интеграции

| Система | Протокол | Если недоступна |
|---|---|---|
| GigaChat API | HTTPS, SDK `gigachat`, OAuth-токен из хранилища секретов | через 5 с — форма из трёх полей (сумма, срок, моя часть); событие ошибки в журнал |
| Страница магазина | HTTPS GET с сервера, защита от SSRF | карточка из названия в адресе + вопрос о цене (случай 23) |
