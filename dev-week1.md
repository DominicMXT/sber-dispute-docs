# Неделя 1 разработки · 15–21 сентября 2026

**Проект:** Finance Assistant — общий бюджет пары · Sber500 × Disrupt
**Репозиторий:** https://github.com/DenisVoronin89/finance-assistant

## Зачем эта неделя

Репозиторий пуст, а продакт всю неделю параллельно проводит 20 интервью с парами и проверяет главное допущение продукта: пары обмениваются информацией о деньгах ежедневно. Если допущение опровергнется, сегмент поменяется на одиночек — поэтому сначала строим то, что нужно при любом сегменте, а связку в пару — последним.

**Цель к 21 сентября:** работающий сквозной сценарий «аккаунт → загрузка выписки → общий бюджет», чтобы со второй недели строить главный экран на настоящих данных, а не на заглушках.

## Приоритет

Неделю не продлеваем. Не успеваем — режем снизу вверх: банки 2–3 и приглашение партнёра, но не сквозной сценарий.

|---|---|---|

| 5 | Приглашение партнёра | Нужно только паре — к этому моменту будут первые итоги интервью |

## Критерии приёмки

У каждого критерия есть условие, при котором он считается проваленным. Критерий без такого условия — пожелание, а не критерий.

### 1. Проект запускается из чистого клона по README
- **Доказательство:** человек, не писавший код, проходит README на чистой машине и получает работающее приложение.
- **Отклонить, если:** нужен шаг, которого нет в README, или в README стек из предложения, а в коде другой без записанной причины.

### 2. Данные бюджета видят только его участники
- **Доказательство:** автотест — пользователь бюджета X запрашивает транзакции, участников и загрузки бюджета Y через каждый эндпоинт и получает отказ.
- **Отклонить, если:** хоть один эндпоинт отдаёт чужие данные или такого теста нет.

### 3. Импорт выписки сходится до копейки
- **Доказательство:** отчёт по реальной выписке каждого из трёх банков — банк, период, число операций, расхождение. Сверка: входящий остаток + поступления − списания = исходящий остаток; если остатков в выписке нет — сверка с итогами за период в приложении банка.
- **Отклонить, если:** расхождение не 0,00 ₽ хоть по одной выписке, или банк «покрыт» только синтетическим файлом.

### 4. Повторная загрузка не плодит дубли, а настоящие одинаковые операции не склеиваются
- **Доказательство:** тест — одна и та же выписка дважды; две выписки с перекрытием периодов; две настоящие одинаковые покупки в один день.
- **Отклонить, если:** после повторной загрузки операций стало больше, или две настоящие одинаковые покупки превратились в одну.

### 5. Продакт сам проходит сценарий пары на стенде
- **Доказательство:** с двумя тестовыми аккаунтами продакт заводит бюджет, приглашает второго по ссылке, оба загружают выписки, оба видят общий список с отметкой, кто платил.
- **Отклонить, если:** сценарий работает только на машине разработчика или требует его подсказки.

### 6. В публичном репозитории нет реальных данных и секретов — за всю историю
- **Доказательство:** сканер секретов (например, gitleaks) по всей истории — 0 находок; в репозитории нет PDF и CSV, кроме помеченных синтетических.
- **Отклонить, если:** реальная выписка или секрет хоть раз попали в коммит, даже удалённый позже.

### 7. Приложение ставится на телефон как приложение
- **Доказательство:** продакт добавляет его на экран «Домой» на iPhone и устанавливает на Android — открывается без адресной строки.
- **Отклонить, если:** открывается как вкладка браузера.

## Не делаем на этой неделе

- QR-код чека и разбор до товара — исключено решением продакта.
- Интеграции с банками.
- Разбор скриншотов уведомлений и GigaChat — неделя 2.
- Главный экран «сколько осталось» и расчёт остатка — неделя 2.
- Web Push — неделя 3. Продуктовая аналитика — неделя 4.
- Реальные выписки и персональные данные в репозитории.
- Открытый доступ и привлечение пользователей.

## Где можно утонуть

- **Писать парсер PDF с нуля.** Есть готовые под MIT: [Sberbank2Excel](https://github.com/Ev2geny/Sberbank2Excel) — выписки Сбера в PDF; [pdfplumber-bank-ru](https://github.com/loginchik/pdfplumber-bank-ru) — Альфа, Озон, Райффайзен, Т-Банк, Яндекс. У [cashflow](https://github.com/4000680/cashflow) лицензия на уровне репозитория не определена — смотреть можно, копировать нельзя, пока не найдётся файл LICENSE.
- **Все форматы всех банков.** Нужен один формат на банк — тот, что банк реально отдаёт клиенту.
- **Вход «как у больших».** SMS, двухфакторка, соцсети — не сейчас. Нужны раздельные аккаунты, и всё.
- **Категории трат правилами вручную.** Это неделя 2, через GigaChat.
- **Инфраструктура на вырост и полировка дизайна.**

## Стек — предложение, не требование

PWA на React + TypeScript + Vite · Python + FastAPI · PostgreSQL · простая очередь фоновых задач · облако программы (если ещё не выдано — любой хостинг для стенда).

Стек предложен под выбор «веб-приложение». Любую часть можно заменить — с причиной одной строкой в README. Деньги считает детерминированный код с тестами, а не модель.

## Что я додумал — проверь и поправь

1. Три банка — те, чьи выписки реально есть у команды. В приоритете Сбер, Т-Банк, Альфа.
2. На каждый банк — один формат, а не оба PDF и CSV.
3. Не меньше полного рабочего дня большую часть недели. Меньше — режем по приоритету.
4. Выписки для проверки — свои, хранятся только локально, в репозиторий не попадают.
5. Бюджет может иметь одного или двух участников — чтобы работа не пропала при смене сегмента.
6. Секреты — ни одного в истории git; на сервере — через хранилище секретов хостинга.
